# Editorial Mechanics Bridge structural inference successor v3

## Decision

V3 removes `no_repeat_ngram_size=8`. The v2 run demonstrated that the generic lexical constraint interfered with JSON syntax: R2 reached EOS but failed JSON parsing before any durable row. This does not identify the failing case because v2 intentionally persisted no partial payload and lacked case-bound failure evidence.

V3 uses a character DFA projected through a tokenizer trie via Transformers' native `prefix_allowed_tokens_fn`. The same DFA and token projection apply to every candidate. It fixes the bound schema prefix, exact case/request/output bindings, outcome enum, JSON string escaping and text ceiling, claim-binding object/array shape, permitted source-span identities, abstention enum, closing object, and terminal-only EOS. No token limit is increased and qualification semantics, requests, candidates, model, and adapters remain unchanged.

Independent post-generation validation repeats EOS, JSON, key order, schema, request binding, answer/abstention structure, claim-index continuity, span membership/order/uniqueness, and limits before any response file or receipt is written.

## Failure evidence

On any per-case failure, the worker writes only `failure.json` with candidate, case ID, request identity, ordinal index, exception class, and a canonical identity. It records that no invalid payload, partial response rows, or receipt were persisted. Exception messages and generated bytes are excluded. The candidate directory remains ineligible, the route exits nonzero, the supervisor writes one terminal BLOCKED event, subsequent candidates do not run, and scoring roots are not created.

## Historical state

V1 scoring artifacts and v2's empty failed output remain immutable historical failure evidence and are ineligible for scoring. A future v3 execution must use new empty roots and requires 168/168 structurally valid EOS rows before packet preparation.
