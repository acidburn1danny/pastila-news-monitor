# A1/A2 blind scoring handoff (fixture closure)

This local successor is tested only with synthetic fixture responses and fixture ratings. It does not authorize the six consuming runs. The published causal protocol at `37846897e4ef69b9ab10aeaadf33a78de16c2098` sets `real_runs_authorized=false` and `optimizer_steps_authorized=0`.

The custodian prepares seven canonical response files: R2 and A1/A2 at each of the three fixed seeds. `prepare_editor_core_bridge_blind_scoring.py` creates 72 shuffled X/Y comparison packets, 24 separate R2 reference packets, and a sealed mapping in three distinct roots. The reviewer receives only the comparison packet root. The sealed map and reference root stay in custodian custody. The answer key and holdout are never inputs to this route.

The reviewer independently scores factual/epistemic safety, editorial quality, and Romanian quality per displayed option, then chooses X, Y, tie, or indeterminate for each comparison. A reason is required for factual/epistemic failures or indeterminate comparisons. The reviewer identity must be supplied externally. The fixture route stores each score as canonical JSON, binds it to the exact packet bytes and packet identity, and creates the file with exclusive creation. It refuses duplicates, cross-packet records, mutations, incomplete inventories, and unexpected files.

Only after all 72 primary records validate can the custodian lock the primary root. The lock manifest binds all 72 record identities and packet hashes; existing records become read-only. Only a locked primary root allows reference handoff. The same reviewer then scores 24 R2 reference packets in a separate root, and the reference phase receives its own complete lock manifest. The sealed arm map remains outside reviewer custody until both phases have closed. No arm comparison or decision is derived by this scoring recorder.

Runbook for fixture verification: `pytest tests/test_editor_core_bridge_blind_score_records.py tests/test_editor_core_bridge_causal_route.py`. The recorder CLI supports `verify`, `lock`, and `reference-handoff`; human record entry has only a tested Python API at present. Human reviewer authentication, a usable reviewer interface, protected physical custody, and independently witnessed/WORM preservation have **not** been closed by fixture tests. Filesystem read-only bits and content hashes detect or discourage mutation; they are not proof that a privileged custodian cannot rewrite local files. These items require a separate live handoff gate before real scoring.

The published consuming shell route has an owner-settable environment flag. That flag cannot override the published protocol's explicit denial of real-run authority. A successor authority and route check must bind execution to a published authorization before any real model load or optimizer step. The final authority audit therefore reports the six runs as **BLOCKED**, even though fixture projection and zero-step validation pass.
