# VNext VOICE Model Candidate & Acquisition Plan v1

The bounded first round uses the existing R2 closure as a zero-acquisition control and two text-only Apache-2.0 challengers whose immutable snapshots were already inventoried and used in the closed EDITOR bake-off. That prior task does not answer the VOICE question, but it supplies exact bytes, revisions, compatibility evidence and reference runtime measurements without adding a new model family.

The challengers are Qwen3-8B in non-thinking mode and Qwen2.5-7B-Instruct. Their verified local copies remain outside VNext and are not runtime dependencies. The recommended acquisition action is a fresh blob-by-blob verification followed by an authorized physical copy into the single VNext product root, atomic publication and a clean-room restore. Download is a fallback requiring separate authority if the existing bytes fail verification.

The bake-off uses 24 new VNext development SourcePackets, three common seeds and per-case/per-seed blind labels. It scores factual drift as a hard gate before commentary quality, Romanian naturalness, relevance, wit, voice fit, repetition and runtime. Results aggregate at case level before unsealing. No candidate can continue after setup mutation, an unsupported concrete claim, identity drift, OOM, excess VRAM, or dependency/license failure.

This plan grants no acquisition, model load, inference, training, selection, promotion or release authority.
