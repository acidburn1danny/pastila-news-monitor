# Editor Core V10 V1.2 targeted R4 corrective round

R4 is a corrective development pack parented directly by R2 step-9. It does
not continue from the rejected R3 adapter. The demonstrated defect is an
attribution overcorrection: preservation of denial and finality while dropping
the suspicion or modal carrier that keeps the central allegation uncertain.

The proposed pack contains 12 new rows: eight attribution/modality examples
and four preliminary/contest examples as counterbalance. It includes 36
deterministic replay anchors, twelve each from retained V10, R1, and R2 training
sources. A separate 12-case holdout contains six cases from each pattern. The
three failed R3 cases are diagnostics only; their requests and targets are not
training inputs.

The proposed recipe uses a fresh optimizer, one epoch, micro-batch one,
gradient accumulation eight, six optimizer steps, and a reduced learning rate
of `1e-6`. Training remains unauthorized. Closure requires byte-exact rebuild,
tokenizer validation, replay provenance, and anti-contamination checks against
all retained corpora including both frozen R2 and R3 holdouts.
